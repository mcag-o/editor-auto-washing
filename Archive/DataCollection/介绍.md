# 介绍

## 项目目的

`DataCollection/` 是一个从零整理后的 Node.js 热榜采集实现，目标是完整承接当前 Python 项目的DataCollection能力，而不是直接依赖某个第三方聚合 API 页面。

它解决的是四件事：

- 将不同平台的DataCollection逻辑拆成独立模块
- 将不同平台格式统一成标准 JSON
- 将请求层能力统一封装为超时、重试、限流、并发池、浏览器回退
- 为后续 API 服务、数据库存储、前端展示提供稳定输入

## 架构说明

### 配置层

`src/config/env.js` 负责读取 `.env` 并归一化为只读配置对象，统一管理：

- 请求超时
- 重试次数
- 重试基线延迟
- 全局并发数
- 默认 User-Agent
- 代理配置
- Cookie 配置
- 浏览器回退开关

### 核心运行时

`src/core/` 负责底层能力：

- `httpClient.js`：请求、JSON/Text 解码、超时、重试
- `rateLimiter.js`：按平台限速
- `concurrencyPool.js`：批量任务并发上限
- `backoff.js`：指数退避
- `errors.js`：统一错误模型
- `browserClient.js`：Playwright 浏览器回退

### 平台适配层

`src/platforms/` 每个平台一个文件。

- JSON API 型平台通过 `defineJsonCrawler()` 构造
- HTML 页面平台通过 `defineHtmlCrawler()` 构造
- 每个平台只关心两件事：如何找到上游列表，如何把单条记录映射成标准条目

### 调度层

`src/scheduler/` 提供两个入口：

- `collectPlatform()`：抓单个平台，失败也返回结构化错误对象
- `collectMany()`：抓多个平台，支持部分成功、部分失败

### CLI 层

`src/cli/run.js` 支持：

- `--platform`
- `--platforms`
- `--all`

输出统一 JSON，可直接重定向到文件或交给上层服务消费。

## 环境变量

复制 `DataCollection/.env.example` 为 `DataCollection/.env` 后可按需修改：

```dotenv
HTTP_TIMEOUT_MS=10000
HTTP_RETRY_COUNT=2
HTTP_RETRY_BASE_MS=250
GLOBAL_CONCURRENCY=4
DEFAULT_USER_AGENT=Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/135.0.0.0 Safari/537.36
HTTP_PROXY=
HTTPS_PROXY=
WEIBO_COOKIE=
XUEQIU_COOKIE=
ENABLE_BROWSER_FALLBACK=false
```

说明：

- `WEIBO_COOKIE`：微博风控场景下建议配置
- `XUEQIU_COOKIE`：雪球风控场景下建议配置
- `ENABLE_BROWSER_FALLBACK=true`：启用 Playwright 回退模式

## 安装与运行

### 安装依赖

```bash
cd DataCollection
npm install
```

### 运行测试

```bash
cd DataCollection
npm test
```

```bash
node DataCollection/src/cli/run.js --platform baidu
```

```bash
node DataCollection/src/cli/run.js --platforms baidu,weibo,zhihu
```

### 全量采集

```bash
node DataCollection/src/cli/run.js --all
```

### 冒烟检查

```bash
cd DataCollection
npm run smoke
```

## 扩展平台指南

新增平台时，按以下步骤进行：

1. 在 `src/platforms/aliases/platformRegistry.js` 中注册新平台元信息
2. 在 `src/platforms/` 下新增平台文件
3. 若是 JSON API，用 `defineJsonCrawler()`
4. 若是 HTML 页面，用 `defineHtmlCrawler()`
5. 在 `src/platforms/index.js` 注册该平台工厂
6. 在 `test/platforms/` 增加对应测试
7. 在 `test/fixtures/` 增加 JSON 或 HTML 夹具
8. 在 `DataCollection.md` 与 `API.md` 中补文档

## 维护建议

- 上游字段变化优先修 `mapEntries()` 与 `mapItem()`
- 上游页面结构变化优先修 selector，不先动公共运行时
- 如果某个平台开始频繁 403，先用 Cookie/代理，再考虑浏览器回退
- 如果要接 HTTP API 服务，可直接在现有 `collectPlatform()` / `collectMany()` 外再包一层 Express、Fastify 或 Hono

## 故障排查

### `403` 或 `401`

- 检查是否需要 Cookie
- 检查是否需要代理
- 检查 `Referer` 和 `User-Agent`

### `ParseError`

- 检查上游字段结构是否变化
- 检查 HTML selector 是否失效
- 检查是否拿到的是风控页而不是目标页面

### 浏览器回退失败

- 先执行 `npx playwright install`
- 检查服务器环境是否允许 Chromium 启动

### 输出为空

- 检查 `.env` 配置
- 检查对应平台是否当前受风控
- 运行单平台模式定位问题，不要直接先跑 `--all`
